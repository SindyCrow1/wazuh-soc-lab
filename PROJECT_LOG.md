# Detection Lab: Wazuh SIEM & ICS Target

## 📌 Описание проекта
Лаборатория для отработки навыков мониторинга, обнаружения и расследования инцидентов ИБ (SOC L1/L2). 
Развернута на VPS (Debian 13), включает в себя SIEM Wazuh и изолированную мишень с уязвимой конфигурацией.

## 🏗 Архитектура
- **VPS (Host):** Debian 13, 8 vCPU, 8 GB RAM.
- **SIEM:** Wazuh 4.9.0 (Manager, Indexer, Dashboard) в Docker.
- **Target (Victim):** Docker-контейнер на базе Debian 12 с SSH-сервером и слабым паролем.

## ⚙️ Выполненные шаги (Setup)
- [x] Установка ОС Debian 13, настройка сети и SSH-доступа (ключи + пароль).
- [x] Настройка ядра (`vm.max_map_count=262144`) для работы Wazuh Indexer.
- [x] Установка Docker и Docker Compose.
- [x] Настройка файрвола UFW (открыты порты 22, 443, 1514, 1515, 55000).
- [x] Развертывание Wazuh (single-node) и генерация SSL-сертификатов.
- [ ] Создание Docker-контейнера-мишени (SSH, пользователь `victim`).

## 🚨 Журнал инцидентов (Incident Reports)
*(Здесь будут записи о проведенных атаках и их расследованиях)*

### Инцидент #1: Обнаружение SSH Brute Force
- **Дата:** 17 октября 2026 г.
- **Тип атаки:** SSH Brute Force (Подбор пароля)
- **MITRE ATT&CK:** T1110.001 (Password Guessing), T1021.004 (SSH)
- **Действия атакующего:** Множественные неудачные попытки входа по SSH на контейнер-мишень (пользователь `victim`).
- **Сработавшие правила Wazuh:** Rule 5760 (sshd: authentication failed) и Custom Rule 100100.
- **Выводы и рекомендации:** 
  1. Система мониторинга Wazuh успешно обнаружила аномальную активность.
  2. Кастомное правило 100100 работает корректно.
  3. Рекомендуется внедрить Active Response (автоматическую блокировку IP) для предотвращения подобных атак в будущем.

## 🤖 Автоматическое реагирование (Active Response)
**Дата:** 17 октября 2026 г.
- **Настроен скрипт:** `fake-block.sh` (имитация блокировки IP через iptables).
- **Правило срабатывания:** Rule 100100 (Custom Rule: SSH Brute Force Attempt Detected).
- **Результат:** При обнаружении брутфорса Wazuh автоматически выполнил скрипт и зафиксировал блокировку IP-адреса `127.0.0.1` в логе `/var/ossec/logs/active-responses.log`.
- **Вывод:** Лаборатория настроена на автоматическое реагирование (SOAR), что позволяет блокировать атаки в реальном времени без участия аналитика.
### Инцидент #2: Обнаружение SQL-инъекции (Web Attack)
- **Дата:** 18 октября 2026 г.
- **Тип атаки:** SQL Injection (Веб-атака)
- **MITRE ATT&CK:** T1190 (Exploit Public-Facing Application)
- **Действия атакующего:** Отправка HTTP-запроса к уязвимому веб-приложению (DVWA) с внедрением SQL-кода (`' OR '1'='1`).
- **Сработавшие правила Wazuh:** Custom Rule 100200 (сработало на основе декодера `web-accesslog`).
- **Выводы:** Wazuh успешно распознал веб-атаку, извлек IP-адрес и URL из логов Apache. Кастомное правило корректно сопоставило событие с MITRE ATT&CK T1190. Для полной интеграции с Dashboard требуется настройка Wazuh Agent на веб-сервере.
